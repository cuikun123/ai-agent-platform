# /review — 质量验收

## 触发时机

- 迭代结束时，全面验收
- 模块完成时，局部验收

## 执行步骤

1. 读取 `docs/plan.md`（看当前迭代的所有任务和验收标准）
2. 读取 `docs/conventions.md`（编码规范作为验收标准）
3. 逐项检查：
   - 任务是否真正完成（不只是标记完成）
   - 代码是否符合 conventions 规范
   - 是否违反 CLAUDE.md 红线
   - 功能是否能正常运行
4. 对照 plan.md 中的验收标准，检查整体目标是否达成
5. 输出验收报告：
   - ✅ 通过的项
   - ❌ 未通过的项 + 具体原因
   - ⚠️ 有风险的项（能跑但有隐患）

## 输出

用户看到：验收报告（通过 / 未通过 / 有风险）
不修改文件，只报告结果

## 后续

- 全部通过 → 可以用 /context 切换到下一个迭代
- 有未通过的 → 用 /build 补齐后再验收

## 错误处理

- 未通过项少（1-3 个）→ 逐个用 /build 修复
- 未通过项多（>3 个）→ 按严重程度排序，先修影响最大的，不要全部推翻重来
- 有风险项 → 记录到 dev-log.md 的遗留事项，视情况决定是否现在修
