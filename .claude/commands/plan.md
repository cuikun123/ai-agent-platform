# /plan — 拆解下一个任务

## 触发时机

- 迭代开始时，拆第一个任务
- /build 完成一个任务后，拆下一个
- 需要调整计划时

## 执行步骤

1. 读取 `docs/plan.md`（看当前迭代的大方向、验收标准和已完成任务）
2. 读取 `docs/state.md`（看进行中的任务）
3. 分析下一步该做什么，向用户提建议：
   - 基于大方向判断优先级
   - 说明为什么这个任务应该下一个做
   - 给出任务描述（一句话，可验证的小功能点）
4. 用户确认后，写入：
   - `docs/plan.md` — 追加新任务行（状态 ⬜）
   - `docs/state.md` — 同步更新

## 输出

用户看到：下一步任务建议 + 理由
文件更新：plan.md + state.md

## 任务颗粒度

- ✅ 刚好：一个可验证的小功能点，做完就能测
- ❌ 太粗：一个完整模块（如"用户认证"）
- ❌ 太细：单个文件（如"创建 RegisterRequest.java"）
- 示例：✅ "注册接口 — Controller + 参数校验"
