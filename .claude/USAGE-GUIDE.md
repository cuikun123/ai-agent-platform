# Harness 操作说明

## 一句话总结

日常开发就是 **/plan → /build** 循环，迭代结束用 /review 验收，切迭代用 /context。

## 命令速查

| 命令 | 什么时候用 | 一句话 |
|------|-----------|--------|
| `/plan` | 迭代开始 / 任务完成时 | 决定下一个该做什么 |
| `/build` | 日常开发（最高频） | 执行任务：提方案 → 写代码 → 自检 |
| `/review` | 迭代结束时 | 逐项验收，输出报告 |
| `/status` | 随时 | 查看当前进度 |
| `/context` | 切迭代时 | 清理旧战场，布置新战场 |

## 完整工作流程

### 1. 开始新迭代

```
/context 迭代一
```

AI 读取 plan.md 中的迭代大方向，清空 state.md，提示你用 /plan 开始拆任务。

### 2. 拆解任务

```
/plan
```

AI 分析下一步该做什么，提出建议。你确认后，任务写入 plan.md 和 state.md。

### 3. 执行任务

```
/build
```

AI 读取规范，提方案给你看。你确认后，AI 写代码 → 自检 → 更新状态 → 记录日志。

完成后 AI 问：继续下一个任务？

### 4. 循环推进

```
/plan → /build → /plan → /build → ...
```

### 5. 查看进度

```
/status
```

随时查看当前迭代完成了多少、当前任务是什么。

### 6. 迭代结束验收

```
/review
```

AI 逐项检查，输出验收报告：
- ✅ 通过 — 功能完成且符合规范
- ❌ 未通过 — 需要用 /build 补齐
- ⚠️ 有风险 — 能跑但有隐患

### 7. 切换下一个迭代

```
/context 迭代二
```

验收全部通过后，切换到下一个迭代，重复步骤 2-6。

## 日常开发示例

### 第一天

```
你：/context 迭代一
你：/plan
AI：建议第一个任务：后端项目骨架
你：可以
你：/build
AI：提方案 → 你确认 → AI 写代码 → 自检 → 完成
AI：继续下一个任务？
你：今天到这里
```

### 第二天

```
你：/build
AI：上一个任务已完成，没有待执行的任务，请先 /plan
你：/plan
AI：建议下一个任务：Result<T> 统一返回 + 全局异常处理
你：可以
你：/build
AI：提方案 → 你确认 → AI 写代码 → 自检 → 完成
```

### 中途查进度

```
你：/status
AI：当前迭代一，大方向 4/8 完成，当前任务：认证登录（进行中）
```

### 迭代结束

```
你：/review
AI：验收报告...
你：/context 迭代二
```

## 核心原则

1. **先 /plan 再 /build** — 不要跳过拆任务直接写代码
2. **提方案必须确认** — AI 提方案后等你说"可以"再动手
3. **一个任务一件事** — 不混合无关改动
4. **plan.md 只增不删** — 历史任务记录永久保留
5. **dev-log.md 只追加** — 做了什么记什么，不删历史
